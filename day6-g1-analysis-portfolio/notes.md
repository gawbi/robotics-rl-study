## 2. 배운 점

1. **보상을 끄면 그 항목의 로그도 0이 된다.**
   Isaac Lab은 가중치가 0인 항목을 계산하지 않고 0으로 기록한다 (`reward_manager.py`).
   그래서 실험 1에서 "발을 얼마나 들었는지"를 잴 수 없었다. 꺼버린 행동은 **다른 지표나 별도 측정**으로 확인해야 한다.

2. **보상 함수가 다르면 총 보상을 비교하면 안 된다.**
   실험 1의 평균 보상 감소(−1.21)는 대부분 빠진 상점(약 0.99) 때문이었다. 넘어짐, 명령 추종, 개별 벌점처럼
   두 실험에서 같은 기준으로 잰 지표로 비교해야 한다.

3. **마지막 값 하나보다 마지막 N회 평균 ± 표준편차를 본다.**
   마지막 값만 보면 `dof_pos_limits`가 +80%, `termination_penalty`가 −100%였지만,
   마지막 100회 평균으로는 각각 +44%, −29%였다. 한 iteration 값은 흔들린다.

4. **"하나만 바꿨다"는 건 설정 파일로 확인한다.**
   RSL-RL은 run마다 `params/env.yaml`, `params/agent.yaml`을 저장한다. 두 파일을 `diff` 해서
   가중치 한 줄과 run 이름만 다르다는 걸 확인했다.

5. **seed 1개 결과는 관찰이지 결론이 아니다.**
   2일차 9강(CartPole 하이퍼파라미터 실험)에서 배운 것과 같다. 표준편차는 한 학습 안의 흔들림이지 seed 사이의 차이가 아니다.

6. **학습은 "넘어지지 않기 → 명령 따라가기 → 부드럽게 움직이기" 순서로 진행됐다.**
   실험 0에서 131번째 iteration에 에피소드 길이가 최대에 닿았고, 그 뒤에 명령 추종(0.42 → 0.94)과
   `action_rate_l2`(−0.43 → −0.17)가 좋아졌다.

7. **설치가 "끝났다"고 성공한 게 아니다.**
   Isaac Lab 설치 중 의존성 하나가 조용히 실패한 경험: [트러블슈팅](../troubleshooting/isaaclab_install_flatdict.md)

## 3. 다음 실험 계획

공통 원칙: 예측 → **하나만** 바꾸기 → seed 3개 → 기록 → 해석. 끈 항목은 로그가 0이 되므로 **무엇으로 잴지 먼저 정한다.**

### 3.1 시드 3개 반복 (가장 먼저)

실험 0·1은 각 조건을 시드 1개(42)로 한 번씩만 학습해서, `feet_slide` 차이가 잡음일 수 있다.

| 할 일 | 바꿀 것 | 확인할 것 |
|---|---|---|
| 실험 0·1을 시드 3개씩 반복 (예: 42, 43, 44) | `--seed 43` 등 | 시드 3개 모두에서 실험 1의 발 미끄러짐 벌점이 더 큰지, 차이가 시드 사이의 흔들림보다 큰지 |

### 3.2 보상 실험

| 실험 | 바꿀 것 (Hydra 덮어쓰기) | 예측 | 무엇으로 잴까 |
|---|---|---|---|
| `action_rate_l2` 끄기 | `env.rewards.action_rate_l2.weight=0.0` | 행동이 급하게 바뀌어 관절 떨림이 커질 것 | 끈 항목은 0으로 기록되므로, play 중 연속 행동 차이 ‖aₜ − aₜ₋₁‖를 직접 기록. `dof_acc_l2`, `dof_torques_l2`도 비교 |
| `flat_orientation_l2` 끄기 | `env.rewards.flat_orientation_l2.weight=0.0` | 몸통이 더 기울어진 채 걸을 것 | play 중 `projected_gravity`(몸통 기울기) 기록, `ang_vel_xy_l2`, 넘어짐 비율 |

### 3.3 PPO 하이퍼파라미터 실험

| 실험 | 바꿀 것 | 예측 | 무엇으로 잴까 |
|---|---|---|---|
| `clip_param` 0.1 / 0.2(기본) / 0.4 | `agent.algorithm.clip_param=0.1` 등 | 0.1은 업데이트가 보수적이라 느리게, 0.4는 빠르지만 흔들릴 수 있음 | 에피소드 길이가 최대에 닿는 iteration, 최종 지표, `Loss/learning_rate` (G1도 `schedule: adaptive`라 KL에 따라 학습률이 바뀌는 것까지 같이 봐야 함) |

### 3.4 도메인 랜덤화

로그의 `env.yaml`을 확인해 보니, G1 평지 설정은 **랜덤화가 이미 대부분 꺼져 있다.**

| 항목 | 현재 설정 |
|---|---|
| 마찰 (`physics_material`) | 고정 (static 0.8, dynamic 0.6) |
| 외력 (`base_external_force_torque`) | 0 |
| 밀기 (`push_robot`), 질량 변화 (`add_base_mass`) | 없음 (null) |
| 관측 노이즈 (`enable_corruption`) | **켜짐** |
| 시작 자세 (`reset_base`) | 랜덤 |

- 그래서 "끄기" 실험은 남은 관측 노이즈를 끄는 것 (`env.observations.policy.enable_corruption=False`)이고,
  예측은 "시뮬레이션 안 지표는 비슷하거나 좋아지지만, sim-to-sim으로 옮겼을 때 더 약해질 것"이다. → 3.5와 함께 검증
- 반대로 마찰 범위나 밀기를 **켜는** 실험이 sim-to-real 관점에서는 더 의미 있을 수 있다.

### 3.5 Sim-to-sim: MuJoCo

- 학습된 정책은 이미 내보내져 있다: `logs/rsl_rl/g1_flat/<run>/exported/policy.onnx`, `policy.pt`
- MuJoCo의 G1 모델에서 같은 관측(관절 순서, 기본 자세, 속도 명령, 관측 노이즈 여부)과 같은 제어 주기(50 Hz)·PD 게인으로 정책을 돌려
  Isaac Sim에서처럼 걷는지 확인한다.
- 실험 0과 관측 노이즈를 끈 정책을 둘 다 옮겨서 비교하면 3.4의 예측을 검증할 수 있다.

### 3.6 Sim-to-real: SO-101 로봇팔

- SO-101 로봇팔로 시뮬레이션 학습 → 실제 로봇 실행까지 한 사이클을 경험한다.
- 목표: 간단한 도달(reach) 과제를 시뮬레이션에서 학습하고, 실제 팔에서 같은 관측·행동 규격으로 실행해 차이를 기록한다.
