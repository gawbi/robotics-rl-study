# PPO 9강 --- 하이퍼파라미터 실험과 결과 해석

## 이번 강의의 목표

하이퍼파라미터를 무작정 바꾸지 않고 **예측 → 실행 → 기록 → 해석** 순서로
실험한다. 이번 실험은 CartPole-v1 환경에서 진행했다. 보상 500은 좋은
성능을 뜻하지만, 한 번 500점을 기록했다고 설정이 항상 우수하다고 결론
내릴 수는 없다.

## 1. 주요 하이퍼파라미터

  설정                            실험에서 사용한 값 역할

설정들은 서로 영향을 주고받으므로 한 번에 하나만 바꿔야 결과를 해석하기
쉽다.

## 2. 실험 원칙

실험 전에 다음을 기록한다.

1.  **변경할 값:** 무엇을 바꾸는가?
2.  **유지할 값:** 나머지 설정은 동일한가?
3.  **예측:** 학습 속도, 성능 변동, 최종 보상이 어떻게 달라질 것 같은가?
4.  **결과:** 처음 500점에 도달한 업데이트는 몇 번째인가? 이후 보상이
    떨어졌는가?
5.  **해석:** 예측과 결과가 일치했는가? 이 결과만으로 확정적인 결론을
    내릴 수 있는가?

예측의 목적은 정답을 맞히는 것이 아니라, 왜 그렇게 예상했는지 설명하고
결과로 가설을 점검하는 것이다.

## 3. `learning_rate` 실험

기준 실험은 `learning_rate=3e-4`, 비교 실험은 `learning_rate=1e-4`였다.

### 기준 실험: `learning_rate=3e-4`

-   5번째 업데이트: 평균 보상 `83.2`
-   10번째: `293.1`
-   15번째: `450.4`
-   20번째: `391.6`
-   25번째: `499.8`
-   26번째: `500.0`
-   이후 48번째 업데이트까지 500점 유지

### 비교 실험: `learning_rate=1e-4`

-   5번째 업데이트: 평균 보상 `75.7`
-   10번째: `188.0`
-   15번째: `297.4`
-   20번째: `382.4`
-   25번째: `470.8`
-   26번째: `481.8`
-   28\~30번째 업데이트에서 약 `417` → `348.9` → `295.1`로 하락
-   45번째 업데이트에서 처음 500점 도달
-   46\~48번째에는 약 `478.9`, `463.2`, `463.2`

### 해석

이번 실행들에서는 `1e-4` 실험이 500점에 더 늦게 도달했고 마지막에 보상이
다시 낮아졌다. 하지만 실행 횟수가 제한되어 있으므로 **학습률을 낮추면
항상 느리거나 불안정하다고 일반화할 수 없다.** 여러 랜덤 시드로 반복해
평균과 변동성을 비교해야 한다.

## 4. `clip_range` 실험

PPO는 다음 비율을 계산한다.

``` python
ratio = th.exp(log_prob - rollout_data.old_log_prob)
```

-   `ratio = 1`: 현재 정책과 이전 정책에서 해당 행동의 확률이 같다.
-   `ratio > 1`: 현재 정책에서 해당 행동의 확률이 더 높다.
-   `ratio < 1`: 현재 정책에서 해당 행동의 확률이 더 낮다.

`clip_range=0.2`라면 clipped objective에 사용되는 비율 범위는 보통
`[0.8, 1.2]`다. `0.1`이면 `[0.9, 1.1]`, `0.05`이면 `[0.95, 1.05]`다.

Clipping은 정책 전체의 변화를 완벽히 제한하는 안전장치가 아니다. PPO
목적함수의 특정 항을 제한해 과도한 업데이트를 억제하려는 방법이다.

### 관찰 결과

**`clip_range=0.2`, `learning_rate=3e-4`** - 26번째 업데이트에서 처음
500점 도달 - 48번째 업데이트까지 500점 유지

**`clip_range=0.1`, `learning_rate=3e-4`** - 19번째 업데이트에서 처음
500점 도달 - 25\~29번째 업데이트에서 보상이 `487.3`으로 낮아짐 - 30번째
업데이트에서 다시 500점에 도달 - 48번째 업데이트까지 500점 유지 - 같은
설정을 반복한 실험에서도 최초 500점 도달은 19회 전후였고, 25회차 무렵
하락한 뒤 다시 회복

**`clip_range=0.05`, `learning_rate=3e-4`** - 48번째 업데이트까지
500점에 도달하지 못함 - 최종 평균 보상 약 `493`

마지막 실험은 전체 로그가 아니라 사용자가 기록한 요약을 바탕으로 한다.

### 해석

이번 실험에서는 `0.1`이 `0.2`보다 빨리 500점에 도달했고, `0.05`는 48번째
업데이트까지 500점에 도달하지 못했다. 하지만 **이 결과만으로 `0.1`이
항상 최선이라고 결론 내릴 수는 없다.**

`clip_range`가 작으면 목적함수에서 허용하는 비율 범위가 좁아져
업데이트가 더 보수적으로 이뤄질 수 있다. 실제 학습 결과는 학습률,
rollout 데이터, 초기화, 랜덤 시드 등에도 영향을 받는다.

## 5. `ratio`와 `clip_fraction` 진단

실험에서 사용한 진단 코드:

``` python
ratio = th.exp(log_prob - rollout_data.old_log_prob)

clip_fraction = (
    (ratio < 1 - clip_range) |
    (ratio > 1 + clip_range)
).float().mean()

print("ratio min:", ratio.min().item())
print("ratio mean:", ratio.mean().item())
print("ratio max:", ratio.max().item())
print("clip_fraction:", clip_fraction.item())
```

첫 미니배치에서 관찰한 값은 대략 다음과 같았다.

``` text
ratio min: 0.99999988
ratio mean: 1.0
ratio max: 1.00000012
clip_fraction: 0.0
```

### 왜 첫 미니배치에서 `ratio ≈ 1`인가?

rollout을 수집한 정책과 첫 최적화 단계에서 비교하는 정책은 파라미터
업데이트 전에는 동일하다. 따라서 같은 관측과 행동에 대한 로그 확률이
거의 같고, `ratio`는 약 1이 된다. 부동소수점 계산으로 아주 작은 오차가
생길 수 있다.

따라서 첫 미니배치에서 `clip_fraction=0`이 나온 것은 일반적으로
정상이다. 이 출력만으로 학습 내내 clipping이 발생하지 않는다고 결론
내리면 안 된다.

### 다음에 확인할 것

첫 미니배치뿐 아니라 최적화가 진행된 뒤에도 `ratio`와 `clip_fraction`을
관찰한다. 예를 들어 각 epoch의 마지막 미니배치에서 출력할 수 있다. 단,
그 값도 해당 미니배치의 진단값이지 모든 업데이트를 대표하는 것은 아니다.

## 6. 보상이 오르다가 떨어지는 이유

PPO 학습 중 보상이 떨어졌다고 반드시 코드가 잘못된 것은 아니다. 정책이
업데이트되면서 이전에 잘하던 행동을 덜 선택할 수 있고, rollout에 포함된
경험과 환경의 확률적 특성도 영향을 줄 수 있다.

이번 실험에서는 500점에 도달한 후 보상이 낮아졌다가 다시 회복하는 현상이
관찰되었다. 이 현상 하나만으로 원인을 특정할 수는 없다. 다음을 함께
확인한다.

-   같은 설정에서 여러 번 실행해도 비슷한 하락이 나타나는가?
-   랜덤 시드가 고정되어 있는가?
-   보상뿐 아니라 `policy_loss`, `value_loss`, `entropy`, `ratio`도 함께
    변하는가?
-   로그가 단일 에피소드 보상인지 최근 여러 에피소드의 평균인지
    확인했는가?

현재 코드의 `ep_rew_mean`은 최근 20개 에피소드의 평균 보상이다. 따라서
평균이 낮아졌다는 사실만으로 모든 에피소드의 성능이 동시에 하락했다고 볼
수는 없다.

## 7. 랜덤 시드와 재현성

PPO에는 신경망 초기화, 행동 샘플링, 미니배치 순서 등 무작위 요소가 있다.
실험을 비교할 때는 시드 설정을 확인한다.

``` python
np.random.seed(0)
th.manual_seed(0)
env = gym.make(env_name)
obs, _ = env.reset(seed=0)
```

이는 난수 발생을 제어하는 예시다. 완전한 재현성은 환경의 시드, 액션
공간의 시드, 라이브러리와 연산의 결정성 등에도 영향을 받는다.

-   **같은 시드로 반복:** 실행이 얼마나 재현되는지 확인한다.
-   **서로 다른 여러 시드로 비교:** 설정의 평균 성능과 변동성을
    평가한다.

하나의 실행 결과는 관찰값이지 확정적인 결론이 아니다.

## 9. 핵심 정리

1.  하이퍼파라미터 실험은 **예측 → 한 가지 설정 변경 → 실행 → 기록 →
    해석** 순서로 한다.
2.  한 번의 실행으로 설정의 우수성을 확정하지 않는다.
3.  `clip_range`가 작을수록 clipped objective의 비율 범위가 좁아지지만,
    성능이 반드시 좋아지거나 나빠지는 것은 아니다.
4.  첫 미니배치에서 `ratio ≈ 1`, `clip_fraction=0`이 나오는 것은
    일반적으로 정상이다.
5.  보상이 떨어졌다가 회복하는 현상은 관찰할 가치가 있지만, 로그
    하나만으로 원인을 단정하지 않는다.
6.  여러 랜덤 시드에서 반복해 평균 성능과 변동성을 비교하면 더 신뢰할 수
    있다.

## 10. 확인 퀴즈

### Q1. `clip_range`를 `0.2`에서 `0.05`로 낮추면?

A. clipped objective의 비율 범위가 좁아진다.\
B. 정책 업데이트가 무조건 더 빨라진다.\
C. 보상이 무조건 500점에 도달한다.

**정답: A.** 학습 속도와 최종 보상은 다른 조건에도 영향을 받으므로 B와
C는 보장되지 않는다.

### Q2. 첫 미니배치에서 `ratio ≈ 1`, `clip_fraction=0`이 나왔다. 가장 적절한 해석은?

A. PPO clipping 코드가 반드시 고장 났다.\
B. 정책 업데이트 전에는 현재 정책과 rollout 정책이 같아 이런 결과가 나올
수 있다.\
C. 학습이 끝났다는 뜻이다.

**정답: B.** 업데이트 이후의 진단값도 확인해야 한다.

### Q3. `clip_range=0.1` 실험 한 번이 `0.2` 실험보다 빨리 500점에 도달했다. 무엇을 결론 내릴 수 있을까?

A. `0.1`은 모든 환경에서 더 좋다.\
B. 이번 실행에서는 더 빨리 도달했지만, 일반적인 우수성을 판단하려면 반복
실험이 필요하다.\
C. 랜덤 시드는 실험에 영향을 주지 않는다.

**정답: B.**
